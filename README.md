# Skald Vault

Skald Vault is a sovereign multi-rail Bitcoin wallet application for advanced users who keep their own keys, choose their own infrastructure, and need explicit custody, privacy, fee, and recovery boundaries.

Current status: initial Kotlin Multiplatform / Compose Multiplatform scaffold with Phase 1 descriptor-native on-chain domain modeling, non-secret Bitcoin backend profile settings with a unified address input, simulated backend configuration validation, non-secret descriptor wallet profile metadata, non-operational coin-control/PSBT draft planning, fail-closed secure-storage and secure metadata persistence boundaries, an app-controlled encrypted local vault design, a pinned vault crypto dependency probe with candidate-level dependency review, a disabled Skald-owned vault crypto provider boundary, a disabled provider-selection boundary, a provider-level KAT contract, a test-only provider KAT harness, Argon2id calibration policy/probe-only planning plus non-final candidate parameter policy, manual Android calibration evidence-capture protocol, Android compatibility/entropy policy, and runtime randomness/provider check modeling with test-only Android and Linux/JVM availability probes, a pinned BDK adapter packaging spike, a local `bitcoind` regtest harness, a desktop-test-only local Electrum-compatible regtest indexer harness boundary, a resolved BDK JVM/Linux binding decision, a desktop-test-only BDK regtest wallet validation boundary, a desktop-test-only BDK regtest/signet address derivation validation boundary, receive-address state/reuse policy modeling, Skald-owned backend observation/UTXO state boundaries, a production backend adapter/endpoint normalization boundary, a disabled production sync service facade with Nodes/Recovery/Privacy status surfaces, and a desktop-test-only BDK Electrum regtest UTXO scan validation path that completes when explicitly run with a local `electrs` binary. This repository does not yet implement real wallet functionality. Do not use it with real funds.

## Targets

- Android APK
- Linux desktop app
- Linux `.deb` package

## Build Commands

The intended Gradle tasks are:

```bash
./gradlew build
./gradlew :composeApp:allTests
./gradlew :composeApp:assembleDebug
./gradlew :composeApp:run
./gradlew :composeApp:packageDeb
```

The local regtest smoke harness is opt-in and requires local Bitcoin Core or Bitcoin Knots-compatible `bitcoind` and `bitcoin-cli` binaries:

```bash
SKALD_RUN_REGTEST_INTEGRATION=1 ./gradlew :composeApp:desktopTest --tests '*Regtest*'
```

The seed-backed BDK regtest wallet validation boundary is also opt-in and desktop-test-only:

```bash
SKALD_RUN_BDK_REGTEST_WALLET_VALIDATION=1 ./gradlew :composeApp:desktopTest --tests '*Bdk*' --rerun-tasks
```

The test-only BDK regtest/signet address derivation validation boundary is opt-in and desktop-test-only:

```bash
SKALD_RUN_BDK_REGTEST_ADDRESS_DERIVATION=1 ./gradlew :composeApp:desktopTest --tests '*AddressDerivation*' --rerun-tasks
```

The test-only BDK regtest UTXO scan validation boundary is opt-in and desktop-test-only. Without the local Electrum harness opt-in, it verifies the safe blocked state requiring a local indexed scan backend:

```bash
SKALD_RUN_BDK_REGTEST_UTXO_SCAN=1 ./gradlew :composeApp:desktopTest --tests '*Utxo*' --rerun-tasks
```

To run the desktop-test-only BDK Electrum scan adapter through a local regtest indexer, both opt-ins and local `bitcoind`, `bitcoin-cli`, and `electrs` binaries are required:

```bash
SKALD_RUN_LOCAL_ELECTRUM_REGTEST=1 SKALD_RUN_BDK_REGTEST_UTXO_SCAN=1 ./gradlew :composeApp:desktopTest --tests '*Utxo*' --rerun-tasks
```

The local Electrum-compatible regtest indexer harness is opt-in and desktop-test-only. It expects a local `electrs` binary plus `bitcoind` and `bitcoin-cli`; if `electrs` is missing it reports unavailable rather than using a public backend:

```bash
SKALD_RUN_LOCAL_ELECTRUM_REGTEST=1 ./gradlew :composeApp:desktopTest --tests '*Electrum*' --rerun-tasks
```

Linux packaging requires a JDK that includes `jpackage`. If Gradle selects an Android Studio JBR without `jpackage`, run:

```bash
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./gradlew :composeApp:packageDeb
```

If the Gradle wrapper has not been generated in a fresh checkout, use a local Gradle installation to run:

```bash
gradle wrapper --gradle-version 8.11.1
```

## Security Status

- Visible balances are static demo/testnet placeholders.
- Mainnet operations are unavailable in the scaffold.
- Development networks are regtest, signet, testnet, and testnet4.
- A seed phrase alone cannot restore every rail; Recovery Center modeling is first-class even in the scaffold.
- Descriptor wallet profiles are non-secret metadata only. The app can save planned profile records, but it does not store descriptor text, xpubs, xprvs, private keys, seeds, nsecs, PSBTs, transaction data, or wallet funds.

## No Managed Infrastructure

Skald Vault is client software. It does not operate wallet infrastructure. Users must configure their own nodes, mints, LSPs, relays, Payjoin directories, and backends when those features are implemented.

The scaffold includes no Skald-operated defaults for:

- Bitcoin Core, Electrum, or Esplora backends
- Lightning nodes or LSPs
- Cashu mints
- Nostr relays
- Payjoin coordinators or directories
- Analytics, notification relays, or fee-taking transaction services

## Architecture Notes

- `composeApp/src/commonMain` holds shared domain models and the shared Compose UI. The UI is split into app shell/navigation, reusable Skald components, and focused screen files.
- `composeApp/src/androidMain` holds the Android launcher.
- `composeApp/src/desktopMain` holds the Linux desktop launcher.
- Domain packages now separate core rails/network state, descriptor-native on-chain models, backend configuration models, strict coin-control models, disabled PSBT workflow models, recovery state, quote modeling, privacy warnings, and Lightning/Cashu/Nostr placeholders.
- `settings` holds small repositories/codecs for user-editable, persistent, non-secret Bitcoin backend profiles, descriptor wallet profile metadata, and coin-control/PSBT draft metadata. Android uses SharedPreferences and desktop uses local config files; these stores only hold non-secret labels, enum/status values, development network choices, backend endpoint fields, trust classification, demo UTXO IDs, draft notes/amounts, acknowledgements, blockers, and disabled workflow states.
- `security` holds the secure-storage service boundary, secure metadata persistence boundary, disabled vault crypto provider boundary, disabled provider-selection registry, and disabled implementations. Android and Linux desktop currently report secure storage as unavailable and do not store seeds, private keys, Nostr nsecs, node credentials, Cashu material, backup keys, observed addresses, UTXO state, address indexes, labels, transaction notes, or wallet history.
- `docs/SECURE_STORAGE_DESIGN.md` defines the future Android/Linux secure-storage design gates. It is a design document only; it does not enable real secret persistence.
- `docs/ENCRYPTED_LOCAL_VAULT_DESIGN.md` defines the app-controlled encrypted local vault architecture, key hierarchy, platform strategy, Tor/network metadata implications, recovery implications, migration/corruption handling, and acceptance criteria required before real secret or sensitive metadata persistence. It is a design document only; it does not implement encryption or persistence.
- `docs/ENCRYPTED_LOCAL_VAULT_CRYPTO_DECISION.md` records the vault crypto/key-lifecycle design decisions: Argon2id as the target KDF, XChaCha20-Poly1305 as the target record AEAD for the candidate-reviewed stack, per-record random nonce policy, key hierarchy, platform wrapping policy, container/versioning strategy, backup/export strategy, corruption/migration behavior, and readiness gates. It is a design record only; it does not add runtime cryptography.
- `docs/ENCRYPTED_LOCAL_VAULT_DEPENDENCY_SPIKE.md` records the vault crypto dependency probe. Tink `1.21.0` and Bouncy Castle `1.84` are pinned in platform source sets so Android and Linux packaging can verify candidate API presence; no vault storage, KDF implementation, AEAD implementation, key generation, persistence, or unlock UI is enabled.
- `docs/ENCRYPTED_LOCAL_VAULT_KAT_VALIDATION.md` records desktop JVM and Android runtime public known-answer-vector validation for Bouncy Castle Argon2id and Tink XChaCha20-Poly1305. It is dependency validation only; Android runtime KATs passed on Pixel 10 Pro XL / Android 16 after raw ADB IP:port targeting, and secure storage remains disabled.
- `docs/ENCRYPTED_LOCAL_VAULT_LIBSODIUM_COMPARISON.md` records the libsodium/Kotlin comparison. Lazysodium Java/Android `5.2.0` exposes relevant APIs but failed Android packaging with duplicate JNA classes and is not left on the runtime classpath; IonSpin KMP libsodium `0.9.5` remains deferred after metadata/POM inspection.
- `docs/ENCRYPTED_LOCAL_VAULT_DEPENDENCY_REVIEW.md` records the Tink/Bouncy dependency, license, Tink keyset/storage, Bouncy Castle Argon2id API, and split-provider review. It promotes the stack only to a candidate-reviewed status; it does not approve production implementation or storage.
- `docs/ENCRYPTED_VAULT_READINESS_POLICY.md` records the code-level encrypted vault readiness models. The models report the vault as not implemented, dependency selection reviewed only at candidate level, KDF/AEAD parameters unverified, candidate KDF parameter policy not final, storage disabled, production persistence blocked, and mainnet disabled. They do not implement encryption, storage, unlock UI, or runtime cryptography.
- `docs/ENCRYPTED_LOCAL_VAULT_CRYPTO_PROVIDER_BOUNDARY.md` records the disabled Skald-owned provider boundary. It models typed provider requests/results/errors, algorithm policy, nonce policy, record purposes, provider-level KAT requirements, and redacted diagnostics while rejecting KDF execution, AEAD execution, key generation, keyset storage, container read/write, persistence, and mainnet.
- `docs/ENCRYPTED_LOCAL_VAULT_PROVIDER_SELECTION_BOUNDARY.md` records the disabled provider-selection registry. It selects `DisabledVaultCryptoProvider` only, lists Tink plus Bouncy Castle as a blocked future candidate, keeps Lazysodium rejected and IonSpin deferred, and treats dependency-level KATs, test-provider KATs, runtime Android compatibility/randomness checks, disabled storage, vault-container review, and mainnet as selection gates.
- `docs/ENCRYPTED_LOCAL_VAULT_PROVIDER_KAT_CONTRACT.md` records the provider-level KAT contract that a future executable Skald-owned provider must satisfy. It models positive KDF/AEAD vectors, negative misuse tests, platform coverage, nonce-policy rejection, redaction requirements, and storage-separation gates; it does not make provider-level KATs pass.
- `docs/ENCRYPTED_LOCAL_VAULT_TEST_PROVIDER_KAT_HARNESS.md` records the test-only provider-level KAT harness. It proves the Skald-owned provider request/result path can carry public Argon2id and XChaCha vectors plus required negative cases on desktop and Android runtime, while production provider execution, vault containers, storage, persistence, and mainnet remain absent.
- `docs/ENCRYPTED_LOCAL_VAULT_ARGON2ID_CALIBRATION.md` records the Argon2id calibration policy and probe-only measurement plan. It models explicit KiB/MiB memory candidates and bounded desktop/Android test harnesses while keeping production KDF execution, provider execution, storage, persistence, and mainnet disabled.
- `docs/ENCRYPTED_LOCAL_VAULT_ARGON2ID_PARAMETER_POLICY.md` records the non-final candidate Argon2id parameter policy: 64 MiB / 3 passes / 1 lane for desktop candidate evidence, 32 MiB / 3 passes / 1 lane for historical high-end Android timing evidence, 16 MiB / 2 passes / 1 lane as a fallback/probe floor only, and supported-Android compatibility planning based on runtime provider/randomness gates rather than mandatory low-end or mid-range model testing. The v1 acceptance contract separately records a shared 64 MiB / t=3 / p=1 review floor, at least 16-byte salt, preferred 32-byte salt, 64-byte derived root material, fail-closed memory behavior, and no silent stored-parameter downgrade. It does not approve production parameters.
- `docs/ENCRYPTED_LOCAL_VAULT_ANDROID_CALIBRATION_CAPTURE.md` records the manual Android calibration evidence-capture protocol and template. It keeps Pixel 10 Pro XL / Android 16 evidence high-end only, rejects ambiguous units and secret-like evidence fields, and cannot approve production KDF execution; low-end and mid-range model evidence is optional parameter/UX evidence, not a compatibility hard blocker.
- `docs/ENCRYPTED_LOCAL_VAULT_ANDROID_COMPATIBILITY_ENTROPY_POLICY.md` records Android supported-baseline compatibility and entropy policy. It separates OS/reviewed-provider cryptographic randomness from optional hardware-backed key protection, forbids language and ad hoc random APIs for vault material, and requires fail-closed user-facing vault-creation warnings when platform/provider/randomness/storage gates are missing or unknown.
- `docs/ENCRYPTED_LOCAL_VAULT_RUNTIME_RANDOMNESS_PROVIDER_CHECKS.md` records runtime randomness/provider check models and test-only Android/Linux availability probes. The probes generate only small non-secret samples, do not persist or log samples, do not prove entropy quality, and do not enable production randomness, key generation, provider crypto, vault storage, or mainnet.
- `docs/ENCRYPTED_LOCAL_VAULT_TINK_RAW_KEY_FEASIBILITY_PROBE.md` records the test-scope Tink raw-key feasibility result `FEASIBLE_PUBLIC_RAW_KEY_API`. Public Tink APIs can construct the pinned XChaCha20-Poly1305 primitive from caller-supplied fixed raw key bytes through a transient in-memory keyset handle, with no persisted keyset, no random Tink-generated vault key, no key rotation, no multiple active keys, no internal APIs, and no reflection. It does not implement production AEAD or approve provider selection.

It pins the review direction to Bouncy Castle Argon2id, Tink XChaCha20-Poly1305, and OS SecureRandom with passphrase-first protection, optional Android wrapping, one explicit suite id, non-key-committing AEAD handling, a separate canonical header commitment before record decrypt, the `unicode-nfc-utf8-no-controls-no-whitespace-v1` passphrase encoding policy, passphrase-derived raw AEAD key material with public Tink API feasibility evidence, bounded Argon2id calibration, and fail-closed acceptance gates. It does not implement or select a production provider.
